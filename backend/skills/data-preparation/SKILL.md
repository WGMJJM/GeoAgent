# 数据准备

围绕当前任务判断数据是否可用，选择必要的整理方式，并保留能够解释整理影响的证据。根据已有信息决定从哪里开始，不把所有检查和清洗变成固定前置步骤。

## 判断依据

- 使用当前任务已核验的数据集与用户明确的业务含义。字段名、文件名和少量样本只能帮助提出解释，不能单独确定字段单位、唯一键或缺失值含义。
- `dataset.inspect` 返回已登记的元信息，不会重新扫描完整文件。当前 CSV、TSV、JSONL 检查最多读取前 1,000 行，`schema.feature_count` 可能只是读取行数；元信息中的样例也不能证明全量分布。任务需要准确总数、缺失比例或唯一性时，通过可用工具或 Python 对相应数据进行实际计算。
- 当已有证据足够且数据满足目标时直接使用。只有缺失信息会改变计算口径或交付含义，且无法通过现有资料取得时，才请求用户补充。

## 选择必要操作

- 优先考虑用户明确指定的处理口径；没有明确口径时，根据问题影响选择保留、标记、排除或转换，并交代影响。不要因为发现空值、重复值或异常值就直接删除。
- 表格字段、关联、去重和聚合涉及口径判断时，按需读取 [表格整理参考](references/tabular.md)。
- 涉及几何修复、坐标系、距离面积单位或栅格对齐时，按需读取 [空间数据参考](references/spatial.md)。
- 使用当前可调用工具的真实参数；必要能力未提供时按项目工具发现规则查找。自定义整理可以使用可用的 `python.execute`，不假设存在通用的清洗、格式转换或 SQL 工具。
- 整理后的数据保存为新输出，并保持原始数据可追溯；临时检查不应生成大量无关交付文件。读取本技能不要求同时读取其他技能。

## 检查整理影响

- 对实际发生的变换检查对应结果：去重核对保留与移除记录，关联核对匹配率及行数变化，类型转换核对失败值，空间处理核对范围、单位和几何状态。
- 检查应符合操作语义。例如一对多关联可能增加行数，裁剪可能合理地产生空结果，不能仅凭数量变化认定失败。
- 有影响结果含义的数据损失、未匹配项或未解决歧义时明确说明。证据足以支撑当前交付后结束检查，不扩展为全数据审计。
